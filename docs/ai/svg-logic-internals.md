# A-03: SVG Engine Internals

This document explains the internal logic of the \`src/sivo/svg/\` module, detailing how SIVO parses, normalizes, and manipulates SVG elements to prepare them for interactive frontend rendering. AI agents should use this guide to understand constraints around SVG node manipulation and programmatic path generation.

## 1. SVG Parsing with \`lxml\`

SIVO uses \`lxml.etree\` for all SVG parsing and manipulation. The core parsing logic is located in \`src/sivo/svg/parser.py\` within the \`SVGParser\` class.

### XXE Vulnerability Protection

When parsing SVG data (either from a file or a string), SIVO explicitly disables entity resolution and network access to mitigate XML External Entity (XXE) injection attacks:

\`\`\`python
# In src/sivo/svg/parser.py
parser = etree.XMLParser(resolve_entities=False, no_network=True)
self.tree = etree.parse(f, parser=parser)
\`\`\`

**Agent Directive:** When writing tests or extending the parsing logic, *never* enable entity resolution or network access in the \`etree.XMLParser\`.

## 2. Node Manipulation Constraints

### The ECharts \`name\` Attribute Workaround

SIVO's interactive frontend engine is built on Apache ECharts. ECharts primarily relies on the \`name\` attribute of SVG elements (rather than the \`id\` attribute) to bind data and events to specific regions in an SVG map.

Many standard SVG files generated by tools like Illustrator or Figma define an \`id\` but lack a \`name\` attribute. To bridge this gap, SIVO's \`SVGParser.process_elements()\` injects a \`name\` attribute matching the \`id\` if the \`name\` attribute is missing:

\`\`\`python
# In process_elements()
elem_id = elem.get('id')
if elem_id:
    elem_name = elem.get('name')
    if not elem_name:
        elem_name = elem_id
        elem.set('name', elem_name)
\`\`\`

**Agent Directive:** When programmatically creating or modifying SVG nodes via the \`add_shape()\` method or direct \`lxml\` manipulation, always ensure that if an \`id\` is present, a corresponding \`name\` attribute is also set.

## 3. Normalization and Metadata

Before processing elements, SIVO applies a normalization step via \`SVGNormalizer\` (in \`src/sivo/svg/normalizer.py\`). A primary task of the normalizer is to resolve \`<use>\` tags by replacing them with deep copies of the referenced elements, applying the necessary transforms.

### Bounding Box Calculations

The \`src/sivo/svg/metadata.py\` module provides the \`get_bounding_box(elem)\` function, which calculates an approximate bounding box \`[min_x, min_y, max_x, max_y]\` for shapes like \`rect\`, \`circle\`, \`ellipse\`, \`line\`, \`polygon\`, \`polyline\`, and \`path\`.

For \`path\` elements, SIVO implements a custom, fast \`PathBBoxCalculator\` that tracks explicit coordinate points from path data commands (e.g., M, L, C, A) to derive conservative bounds.

## 4. Programmatic Generation (e.g., Cards)

SIVO supports dynamic programmatic generation of native SVG elements, such as the KPI cards implemented in \`Sivo.add_card()\` (found in \`src/sivo/core/sivo.py\` and delegated to \`Infographic.add_card()\` in \`src/sivo/core/infographic.py\`).

### Auto-Scaling and Anchor Points

Cards are dynamically generated relative to the bounding box of a target SVG element (the "anchor"). This is crucial because SIVO maps are often responsive.

\`\`\`python
# Logic from Infographic.add_card()
target_elem = self._element_lookup.get(element_id)
bbox = target_elem['bbox']
bbox_width = bbox_max_x - bbox_min_x
bbox_height = bbox_max_y - bbox_min_y

# Relative positioning
abs_left = bbox_min_x + _parse_val(str(left), bbox_width)
\`\`\`

When writing functions to inject new elements dynamically, agents must:
1. Look up the anchor element and retrieve its \`bbox\`.
2. Parse relative values (e.g., \`"50%"\`) against the anchor's width/height.
3. Calculate absolute SVG coordinate positions before generating the new nodes.
4. Programmatically add elements using standard \`lxml\` DOM manipulation or \`parser.add_shape()\`.
